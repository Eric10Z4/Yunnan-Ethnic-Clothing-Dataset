## 一、项目背景与核心考核指标

本次期中作业聚焦数据集构建，**不要求训练分类或生成模型**。任务书要求至少覆盖 5 个经核验民族类别；图像生成方向不少于 1,500 组，建议每类不少于 150 组。当前覆盖 10 类，但少数类别未达到每类建议量，具体见下表。主要图像与标注要求如下：
1. **真实可追溯**：类别严格依据可信文献、博物馆典藏或原始发布页面，严禁凭外观主观推测。
2. **纯白底与单主体**：RGB 严格为 `(255, 255, 255)`，仅包含单件服饰或单人穿着，杜绝合影拼图。
3. **严格几何约束**：
   - 居中度：主体中心横纵偏差 $\le 10\%$（$\le 51.2$ px）。
   - 主体尺度：主体外接框较长边 $\ge 60\%$（$\ge 307.2$ px）。
   - 画布尺寸：等比例缩放并白色补边至 $512 \times 512$ 像素。
4. **高质量图文对齐**：细粒度结构化 JSON 属性 + 规范英文描述，未知属性标 `unknown`。

## 二、数据构建流程

构建工作包括来源登记、清洗去重、主体处理、任务标注、质量检查与交付。各步骤的代码及日志保留在仓库中。

```text
来源登记与采集
    ↓
格式、分辨率、清晰度检查及 MD5 / pHash 去重
    ↓
主体分割、白底合成、等比例居中补边至 512×512
    ↓
双图 VLM 质检及后续定向人工复核
    ↓
结构化属性与英文 caption 标注、受控词表处理
    ↓
五份记录对齐、同源跨集核验与交付
```

**阶段台账分开记录**：初始清洗批次为 6,259 张，排除 835 张，保留 5,424 张；独立双图质检候选池为 6,744 张，其中 1,765 条 PASS、4,979 条 FAIL。两组台账口径不同，分别记录，不作为连续数量漏斗。最终主集在后续选样、复核与修复后定稿为 1,512 组。

## 三、当前建设进展与数据资产台账

### 1. 阶段一：高通量多源采集
初始清洗批次包含 **6,259 张候选图像**。当前原始来源台账见 `dataset/raw/raw_metadata.csv`，6,259 是历史批次数，不代表当前 raw 目录或台账的总量。

### 2. 阶段二：六级漏斗清洗与感知去重
历史清洗报告记录的 6,259 张候选图像，经 `code/02_clean_and_dedup.py` 处理后：
- **清洗后保留**：**5,424 张**（留存率：`86.66%`）
- **拦截剔除总数**：**835 张**（逐样本原因详见 `dataset/cleaned/exclusion_log.csv`）
  - 感知哈希近重复 (pHash): 461 张
  - 像素级完全重复 (MD5): 281 张
  - 分辨率过小 / 极端比例: 67 张
  - 文件损坏 / 解码异常: 18 张
  - 模糊 / 虚焦: 7 张
  - 单色占位图: 1 张

针对上衣属性被误清空的 19 条记录开展定向复核，恢复其中 16 条的可见上衣属性，另外 3 条保留 `none`。样本 1120 的重分割、袖缘局部背景清理及复现由贾子钊负责，脚本为 `code/clean_1120_cuff.py`，材料见 `dataset/reproducible_1120/`。

## 五、环境与核验命令

### 环境准备
```bash
# 克隆代码仓库
git clone https://github.com/Eric10Z4/Yunnan-Ethnic-Clothing-Dataset.git
cd Yunnan-Ethnic-Clothing-Dataset

# 安装 Python 依赖
pip install -r code/requirements.txt
```

### 定稿数据核验

以下完整门禁与默认 1120 核验命令在包含合法取得图像的本地完整交付目录运行；仅克隆 metadata-only 仓库不会取得全量主集图像。

```bash
# 核验 1,512 条记录、图像规格、五份记录对齐及同源跨集情况
python code/04_quality_audit.py --full

# 调用生产标注函数的 10 项离线测试
python code/test_pipeline_offline.py

# 核对本地 1120 定稿图像哈希
python code/clean_1120_cuff.py --verify
```

历史清洗与标注脚本用于构建阶段。重新构建可能产生新结果，应在单独目录运行；定稿核验不需要重新导出或覆盖 `metadata.csv`。
